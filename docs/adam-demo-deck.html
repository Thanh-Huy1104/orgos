The finding — spec drift is the real problem

  1. Solo strong agent (Copilot CLI). One generalist reads the whole spec each cycle.
  2. Multi-role waterfall. PO → Architect → Test → DevSecOps. What every LLM drafts when asked for “an agentic team.”
  3. Scrum (this repo). Flat specialists, shared board, parallel worktrees, merge queue, replan loop.
Measured against a held-out reference test suite (110 tests written from the spec, not by any agent):
Solo Copilot ~75% pass · Waterfall ~23% pass · Scrum ~16% pass

The intuitive multi-agent topologies both fail badly. Not because the agents can't code — but because each agent only sees one story. Interface names drift across packages. Solo Copilot maintains context and stays spec-conformant. This is a coordination-vs-context problem, not scrum-vs-waterfall.

n=2 pilot runs per arm on my laptop this week. The direction is stable across runs; formal n=3 study running now.

What the drift looks like — real code, same spec

Spec said (Story 4, analyzer)


remove_stopwords(tokens, lang="en")
bigrams(tokens)
apply_pipeline(tokens, filters=[...])

Three module-level functions. Deterministic contract.

What scrum built


class StopwordFilter:
    def __init__(self, stopwords=None): ...
    def filter(self, tokens): ...

class NgramGenerator:
    def __init__(self, n=2): ...
    def generate(self, tokens): ...

Class-based. Different names. Passes scrum's own tests. Fails the spec's contract.

Same pattern across query.parse vs parse_query, missing Wildcard AST node, missing QueryNode alias, class-based ranker vs functional ranker. The test agent writes tests against whatever the architect built, not what the spec said.

What would fix it — the missing gate

The bug is topology-level, not agent-level. The fix is a new gate in the scrum board:

  1. Spec-conformance gate. Before a story merges, run reference tests derived from that story's AC. Currently the AC gate is LLM-graded soft-check. This makes it a hard check against machine-parseable contract.
  2. Shared type-stub file. Auto-generated from the spec at run start; every architect imports from it. Turns “function name drift” into a compile error, not a silent test-pass.
  3. Cross-story linter. After each merge, run a static check that every declared files_to_touch import path resolves. Missing modules = fix-up story next sprint.
The prediction: with the conformance gate, scrum's reference-suite pass rate should approach or exceed solo Copilot's — because scrum's parallelism advantage remains, but drift gets caught before it lands. Worth the next two weeks to test.
