goal: Turn this Flask app into a production-shape Notes API with 7 independent components, each in its own directory: 1. auth/ — JWT auth (register/login/refresh, bcrypt password hashing). auth/models.py, auth/store.py, auth/routes.py. 2. notes/ — CRUD for Notes with owner-scoped access. notes/models.py, notes/store.py, notes/routes.py. Uses auth for owner-check. 3. folders/ — Hierarchical folder tree (folders contain folders or notes). folders/models.py, folders/store.py, folders/routes.py. 4. tags/ — Many-to-many tags on notes. tags/models.py, tags/store.py, tags/routes.py. 5. search/ — Full-text search endpoint GET /notes?q=... — search/store.py, search/routes.py. 6. ratelimit/ — 10/min per-user on write endpoints. ratelimit/middleware.py. 7. docs/ — OpenAPI at /docs and /health endpoint reporting DB + auth-store status. docs/routes.py. Every subsystem has its own `tests/test_<component>.py` file. Every architecture story (data-model or algorithm decision) must add a wiki/DECISIONS.md entry. Integration file app.py is the ONLY shared file — it just imports and registers each components blueprint. Strict rule: a story working the `auth` subsystem must NOT touch files in notes/, tags/, folders/, search/, ratelimit/, or docs/. Cross-component work goes in app.py as a separate integration story.
